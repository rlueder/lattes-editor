# Agent instructions: lattes-editor

Local-first web app that loads a Lattes CV XML export, edits it in the
browser, and writes XML that the Lattes "Importar" dialog accepts. Personal
FOSS project (MIT). It is not part of the precisa-saude ecosystem, but it
follows the same code standards: the shared ESLint, Prettier, tsconfig and
commitlint configs are installed from `@precisa-saude/*` and used unchanged.

The plan lives in `docs/lattes_implementation_guide.md`. The contract for
the exporter is section 5.1 of `docs/lattes_editor_reconnaissance.md`; read
it before touching `src/import-export/`.

## Personal data, the first rule

A real Lattes export carries CPF, RG, birth date and place, parents' names
and passport number.

- Never commit a real export or anything derived from one. `private/`,
  `fixtures/real/` and `CV_*` are gitignored; keep it that way.
- `private/lattes_schema_analysis.xlsx` contains real personal data. It
  stays out of git.
- The app never sends the document anywhere. Network calls (Crossref,
  ORCID, from milestone 2) carry only a DOI or an ORCID iD. The one
  exception, approved by the owner on 2026-10-11: the CV photo is loaded
  from CNPq (`servicosweb.cnpq.br/.../servletrecuperafoto`) with the CV's
  10-character code, so it always matches Lattes. Never log the document,
  never put any of it in a URL.
- The browser bridge follows "Model C" (decided 2026-10-11): an extension
  that posts to Lattes from the user's own logged-in session, one change at
  a time, read back after each write. No credentials ever pass through us.
  The desktop app never opens Lattes itself (no embedded CNPq window): it
  hands changes to the extension, which posts from the user's own browser
  (decided 2026-10-11).
- Test data is synthetic, generated by `scripts/gen-fixtures.ts`.

## Data integrity

Same rule as the ecosystem: never fabricate values that must come from an
authoritative source. In this repo that means:

- Schema facts come from the XSD (`schema/CurriculoLattes_12_09_2022.xsd`)
  or from an observed export. `schema/patch.json` lists only attributes
  seen in a real export; do not add ones that "probably exist".
- Import behavior (sequence numbers, duplicates, accepted file shapes) is
  what was observed on the live platform and recorded in the docs. An
  untested assumption is marked as untested, never presented as fact.
- pt-BR labels for Lattes concepts should match the Lattes forms. Until a
  label has been checked against the form, it comes from the generated
  humanizer, not from a guess written by hand.

## Invariants the code must keep

- Round-trip fidelity: load then save produces the same bytes. The parser
  keeps every attribute and element, known or unknown, in file order.
  `tests/roundtrip.test.ts` enforces it; a real export dropped into
  `fixtures/real/` is tested locally too.
- Latin-1 is done by hand (`src/model/latin1.ts`). Do not use
  `TextDecoder('iso-8859-1')`: it is windows-1252 per WHATWG.
- Child order follows the XSD sequence. Insert with
  `insertInSchemaOrder`; never append to a container directly.
- `SEQUENCIA-PRODUCAO` is one global counter. New items get numbers above
  the export's maximum and never reuse a gap (guide, section 3.2).

## Generated files

| Source                    | Command             | Output                                                                    |
| ------------------------- | ------------------- | ------------------------------------------------------------------------- |
| XSD + `schema/patch.json` | `pnpm gen:schema`   | `schema/CurriculoLattes_2022_patched.xsd`, `src/schema/lattes.{json,ts}`  |
| `src/schema/lattes.json`  | `pnpm gen:fixtures` | `fixtures/synthetic_{full,minimal}.xml`, `fixtures/synthetic_minimal.zip` |

Regenerate and commit the outputs in the same commit as the source change.
`pnpm validate:fixtures` checks every fixture against the patched XSD with
`xmllint`.

## Code standards

Shared with the precisa-saude ecosystem:

- Node 22+, pnpm, TypeScript strict with `noUncheckedIndexedAccess`.
- ESLint `@precisa-saude/eslint-config` (base + react), Prettier
  `@precisa-saude/prettier-config`, commitlint
  `@precisa-saude/commitlint-config` with this repo's scopes in
  `.commitlintrc.cjs`.
- Husky: pre-commit runs lint-staged and the tests; pre-push runs format
  check, lint, typecheck, tests and coverage. Never bypass hooks.
- Vitest with an 80% threshold on all four metrics. When coverage fails,
  add tests; never lower the threshold. React components and the
  IndexedDB store are excluded from unit coverage and belong to the
  Playwright flows (milestone 3).
- Ask before adding a runtime dependency. Today there are three: React,
  React DOM and Dexie. ZIP and XML handling are in-house on purpose.

Repo-specific:

- Relative imports carry the `.ts`/`.tsx` extension, so scripts run with
  plain `node` (type stripping). Keep syntax erasable
  (`erasableSyntaxOnly`): no enums, no parameter properties.
- The build must work from `file://`: `vite.config.ts` inlines the bundle
  into `index.html`. Do not introduce code splitting or external assets.

## Language and writing

- Identifiers in English. UI text, code comments, commit messages and PR
  text in pt-BR with full accents.
- Every document in the repository that a person reads (README, everything
  in `docs/`, issue and PR templates) is pt-BR, for the general Brazilian
  public. Only the agent-facing files (this one, `CLAUDE.md`) stay en-US.
- Commit messages: Conventional Commits, type in English, description in
  pt-BR. No AI attribution lines (the commit-msg hook blocks them).
- Prose for humans avoids machine cadence (matched pairs, tricolons,
  aphoristic endings) and never uses em dashes. Test data may contain
  them on purpose.
